## Зачем

Ты работаешь с несколькими проектами одновременно: Django-приложение с `celery worker` и
`celery beat`, FastAPI, что-то на Node. Обычно это означает кучу открытых терминалов,
`cd` по папкам и попытки вспомнить, в каком окне что запущено.

ProjectControl заменяет эти окна одной панелью в браузере:

- **корневая папка** — указал один раз, дальше панель сама определяет тип проекта и предлагает команды;
- **строка команды** — пишешь `python app.py` или `celery -A src.settings.celery worker`, как в терминале;
- **галочки Celery** — поставил рядом и получил `worker` + `beat` из того же корня;
- **логи внизу, как терминал в PyCharm** — вкладка на каждый процесс, поиск, регулируемая высота;
- **лимит строк** — хранится только кольцо последних N строк, память не растёт бесконечно;
- **кнопки** — открыть сайт, открыть админку Django, открыть проект в IDE, открыть папку;
- **всё сохраняется** — проекты, процессы, окружения, шаблоны. Ничего не вводится дважды.

## Быстрый старт

```bash
git clone https://github.com/<твой-ник>/ProjectControl.git
cd ProjectControl

python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # Linux / macOS

pip install -r requirements.txt
python run.py
```

Панель откроется на **http://127.0.0.1:8770/** и сама запустится в браузере.

На Windows можно вообще без команд — просто двойной клик по **`start.bat`**.
Скрипт сам создаст `.venv`, поставит зависимости и запустит панель.

## Установка

### Требования

| Что | Версия |
|---|---|
| Python | 3.10 или новее |
| ОС | Windows / Linux / macOS |
| Браузер | любой современный (Chrome, Edge, Firefox) |

Сборка не нужна: это чистый Python + обычные JS-файлы, без Node.js и без фронтенд-сборщика.

### Шаг 1. Клонировать и перейти в папку

```bash
git clone https://github.com/<твой-ник>/ProjectControl.git
cd ProjectControl
```

### Шаг 2. Создать виртуальное окружение

```bash
# Windows
python -m venv .venv
.venv\Scripts\activate

# Linux / macOS
python3 -m venv .venv
source .venv/bin/activate
```

### Шаг 3. Поставить зависимости

```bash
pip install -r requirements.txt
```

Ставится три пакета: `fastapi`, `uvicorn`, `pydantic`. Если хочешь тесты:

```bash
pip install -r requirements-dev.txt
```

### Глобальная установка (необязательно)

```bash
pip install -e .
projectcontrol          # та же панель, но доступна как команда
```

## Запуск

```bash
python run.py
```

Увидишь баннер с адресом и подсказкой:

```
===========================================================
 ProjectControl запущен

 Интерфейс:  http://127.0.0.1:8770/
 API:        http://127.0.0.1:8770/api/health
 Настройки:  C:\Users\<юзер>\AppData\Roaming\ProjectControl\projects.json

 Остановить: Ctrl+C
===========================================================
```

### Ключи запуска

| Ключ | Что делает |
|---|---|
| `--port 8780` | запустить на другом порту |
| `--host 0.0.0.0` | открыть доступ из локальной сети |
| `--no-browser` | не открывать браузер автоматически |
| `--no-fallback-port` | не искать свободный порт, если занято (и упасть с ошибкой) |

### Если порт занят

Панель не упадёт — она сама возьмёт следующий свободный порт и напишет, на каком:

```
Порт 8770 занят другим приложением.
ProjectControl будет доступен на порту 8771.
```

Закрепить порт можно в настройках или флагом `--port`.

## Добавление первого проекта

1. Нажми **«+ Добавить проект»** → **«Обзор…»** → выбери корневую папку проекта.
   Поле «Недавние папки» само подставит последнюю использованную.
2. Нажми **«Анализ»**. Панель просканирует папку и определит:

| Что нашли | Что предложат |
|---|---|
| `manage.py` | `{python} manage.py runserver 127.0.0.1:8000` |
| `manage.py` + `src/settings/celery.py` | `runserver` + `worker` + `beat` с готовым `-A` |
| `main.py:app = FastAPI()` | `{python} -m uvicorn main:app --reload --port 8000` |
| `package.json` | `npm run dev` + найденные скрипты `worker`/`beat` |
| `.venv` или `venv` | путь к интерпретатору подставляется сам |
| `.env` | переменные будут подхватываться при запуске |

3. Поправь команду, если нужно, и нажми **«Сохранить»**.

Готово. На карточке проекта появятся кнопки запуска и нижняя панель логов.

## Celery: worker и beat

Отдельная секция в форме проекта. Работает для любого проекта, не только Django.

**Путь к приложению celery** — то, что идёт после `-A`. Обычно панель находит его сама
(ищет `Celery(...)` в `settings/`, `celery.py`, `tasks.py`), но поле всегда можно поправить руками.

Поставь галочку **celery worker** и/или **celery beat** — появятся процессы:

```
celery -A src.settings.celery worker --pool=solo --loglevel=info
celery -A src.settings.celery beat --loglevel=info
```

Если задан интерпретатор (своё или общее окружение), команды автоматически станут:

```
{venv}\Scripts\python.exe -m celery -A src.settings.celery worker --pool=solo --loglevel=info
{venv}\Scripts\python.exe -m celery -A src.settings.celery beat --loglevel=info
```

Это сделано специально: worker и beat гарантированно работают на том же окружении,
что и веб-приложение, даже если глобального `celery` в системе нет.

Порядок запуска: `worker` стартует раньше `beat`, поэтому задачи не потеряются при перезапуске.

### Дополнительные процессы

Кнопка **«+ добавить процесс»** — для Flower, миграций, отдельных скриптов:

| Имя | Тип | Команда |
|---|---|---|
| flower | web | `celery -A src.settings.celery flower --port=5555` |
| migrate | task | `python manage.py migrate` |

## Окружение .venv

Одно поле принимает **и папку, и файл**:

```
C:\Projects\myapp\.venv                  ← папка
C:\Projects\myapp\.venv\Scripts\python.exe  ← файл
```

Что происходит при запуске процесса:

1. выставляется `VIRTUAL_ENV`;
2. `<venv>\Scripts` (на Linux — `<venv>/bin`) добавляется **в начало `PATH`**;
3. вычищаются `PYTHONHOME` и `PYTHONPATH`, которые ломают venv;
4. если команда начинается с `python`, `celery`, `uvicorn`, `flask` — берётся исполняемый
   файл **из venv**, а не системный;
5. если `celery` в venv нет — выполняется `<python> -m celery ...`.

В лог пишется первая строка `окружение: ...`, чтобы всегда было видно, что именно запустилось.

### Приоритет

```
интерпретатор процесса  →  интерпретатор проекта  →  общий .venv из настроек  →  python из PATH
```

В форме проекта поле **«Окружение этого проекта»** переопределяет общую настройку.
Оставь пустым — возьмётся общий `.venv` из настроек.

## Автозапуск и автоперезапуск

**Автозапуск.** В форме проекта есть галочка «Запускать этот проект при старте ProjectControl».
Она действует на все процессы проекта сразу. Общий выключатель — в настройках
(«При старте панели запускать проекты с галочкой „авто“»). Процессы стартуют с задержкой
0,4–0,6 с между собой, чтобы тяжёлые проекты не стартовали в один момент.

**Автоперезапуск при ошибке.** Включён по умолчанию. Если процесс упал, панель поднимет
его снова через указанный интервал — по умолчанию **каждые 10 секунд**, без нарастающей
задержки. В форме проекта это поля «Автоперезапуск при ошибке» и «Повторять через, секунд».

В лог падает строка `Перезапуск через 10 сек`, так что падения видно сразу.

Остановка вручную автоперезапуск отменяет — он не сработает после твоего `■`.

## Панель логов

Внизу окна — терминал в духе PyCharm.

- **Вкладка на каждый процесс.** Для проекта с `web` + `worker` + `beat` будет три вкладки.
  Название включает проект, если процессов несколько: `shop · worker`. На вкладке горит
  точка статуса и счётчик непрочитанных строк.
- **Высота регулируется** — тяни верхнюю границу панели мышкой. Высота сохраняется в браузере.
  Кнопка `⤢` разворачивает панель почти на всё окно.
- **Поиск** — поле в шапке панели. Фильтрует только активную вкладку, не мешая остальным.
  Если ничего не нашлось, будет написано об этом прямо в консоли.
- **Автоскролл** — сам отключается, если пролистать вверх, и обратно включается,
  когда вернёшься к концу.
- **Очистить** — чистит активную вкладку.
- **Лимит строк** — в настройках проекта. Хранится кольцо: при переполнении старые строки
  удаляются, а над консолью появляется подсказка, сколько всего было отброшено.

Горячие клавиши: `Ctrl + \`` открывает и скрывает панель, `Esc` закрывает меню и окна.

Стили строк: обычный вывод — серый, команда `$ ...` — синяя, служебные сообщения панели —
курсивом, ошибки — красные с полосой слева.

**Шапка окна**

| Кнопка | Действие |
|---|---|
| `+ Добавить проект` | новый проект |
| `Шаблоны` | готовые наборы процессов |
| `Настройки` | общие настройки |
| `Остановить всё` | остановить все процессы всех проектов (с подтверждением) |

**Карточка проекта**

| Где | Кнопки |
|---|---|
| Шапка | `Логи` (со счётчиком непрочитанных) и `⋯` |
| Строка процесса | `▶`/`■` — старт/стоп, `⟳` — перезапуск (есть только у остановленного) |
| Нижний ряд | `▶ Запустить всё`, `⟳`, `■`, `Открыть сайт ●`, `Админка`, `В IDE` |
| Меню `⋯` | Настроить проект, Показать логи, Открыть папку, Открыть в IDE, Сохранить как шаблон, Удалить проект |

Зелёная точка у «Открыть сайт» означает, что порт отвечает. Клик по пути проекта открывает папку.
`⟳` и `■` неактивны, когда ничего не запущено.

Команда открытия в IDE задаётся в настройках проекта: `code {root}`, `pycharm64 {root}`,
`idea64 {root}`, `subl {root}`. Работают алиасы `vscode`, `pycharm`, `idea`, `notepad`.

## Шаблоны

Чтобы не настраивать однотипные проекты заново.

**Встроенные:** Django, Django + Celery (worker + beat), Django + Celery (`src.settings.celery`),
Celery (только worker + beat), Celery Flower, FastAPI (`uvicorn --reload`),
FastAPI (`python -m uvicorn`), Flask, Python-скрипт, Node (`npm run dev`), Пустой.

Применение: **«Шаблоны»** → «Применить к новому проекту» → выбрать папку → сохранить.
Либо внутри формы проекта: «Применить шаблон» → «Применить».

Свой шаблон: настроил проект как надо → **⋯** → **«Сохранить как шаблон»**.
Все процессы, адреса и окружение сохранятся и будут применяться в один клик.

## Где хранятся данные

Всё в одном JSON-файле, который пишется атомарно:

| ОС | Путь |
|---|---|
| Windows | `%APPDATA%\ProjectControl\projects.json` |
| Linux | `~/.config/ProjectControl/projects.json` |
| macOS | `~/Library/Application Support/ProjectControl/projects.json` |

Переопределить можно переменной окружения `PROJECTCONTROL_HOME`.

Файл можно редактировать руками (например, чтобы поправить команды у десятка проектов разом)
— панель перезапустит их при следующем старте.

## Docker

Панель запускает **твои локальные проекты**, поэтому контейнеру нужен доступ к диску с ними.

```bash
docker build -t projectcontrol .

docker run -d --name projectcontrol \
  -p 8770:8770 \
  -v C:/Projects:/projects \
  -v projectcontrol-data:/data \
  projectcontrol
```

Открой <http://127.0.0.1:8770/> и указывай корневые папки вида `/projects/<имя-проекта>`.

Тома:

| Том | Зачем |
|---|---|
| `/projects` | твои проекты (монтируется с хоста) |
| `/data` | настройки и база панели (переживает пересоздание контейнера) |

Образ для проверки сборки, который прогоняет тесты при старте:

```bash
docker build -f Dockerfile.test -t projectcontrol-test .
docker run --rm projectcontrol-test
```

Готовые команды — в `docker-compose.yml`.

## Как это устроено

```
projectcontrol/
├── config.py     пути, порт по умолчанию, лимиты
├── models.py     Project / Target / Template, сборка команды, разбор .venv
├── store.py      JSON-хранилище с атомарной записью + встроенные шаблоны
├── detect.py     определение типа проекта, поиск venv, точка входа celery
├── runner.py     запуск/остановка/перезапуск, активация venv, стриминг логов
├── logs.py       кольцевой буфер логов
├── bus.py        рассылка событий в WebSocket
├── opener.py     открытие папок, IDE и URL
├── server.py     FastAPI: REST + WebSocket + статика
└── static/       веб-интерфейс (без сборщика)
```

Пара решений, которые стоит знать:

- **Логи — кольцо.** `collections.deque(maxlen=N)`, старые строки вытесняются, память постоянна.
- **Процессы без отдельных окон.** Вывод перенаправляется в трубу и разбирается построчно
  двумя потоками на процесс.
- **Остановка мягкая, потом жёсткая.** Сначала `CTRL_BREAK_EVENT` (Windows) или `SIGTERM`
  (POSIX) — Django и Celery успевают завершиться корректно; по истечении таймаута —
  `taskkill /T /F` по всему дереву.
- **Никакого REPL.** Процесс без команды, скрипта, модуля или аргументов не запускается —
  иначе интерактивный питон без консоли засыпает трейсбеками. Понятная ошибка вместо мусора.
- **Никакой магии в резолве.** Порядок поиска исполняемого файла явный:
  явный путь → папка окружения → исполняемый файл внутри venv → `PATH` → интерпретатор проекта.

## Решение проблем

**Окно `.bat` сразу закрылось.** Панель пишет причину и ждёт нажатия клавиши.
Чаще всего виноват занятый порт — запусти с `--port 8780`.

**`ModuleNotFoundError: No module named 'fastapi'`.** Процесс пошёл не из того окружения.
Проверь строку `окружение: ...` в логе. Если там `python из PATH`, а не `.venv` —
задай окружение в настройках или в форме проекта.

**`[WinError 5] Отказано в доступе`.** В команду попала папка вместо интерпретатора
(например `.venv\ -m celery`). Панель теперь чинит это автоматически при запуске,
но лучше пересохранить проект — команда пересоберётся с `{python}`.

**Celery не стартует, `celery: command not found`.** Укажи окружение — панель выполнит
`<python> -m celery`. Если celery не установлен в venv, поставь: `pip install celery`.

**Бесконечный поток сообщений об ошибке.** Раньше процесс падал и перезапускался по кругу.
Сейчас по умолчанию перезапуск раз в 10 секунд — увеличь интервал в настройках проекта
или выключи автоперезапуск.

**Порт занят твоим же проектом.** Например `manage.py runserver 127.0.0.1:8770`.
Панель сама перейдёт на 8771, либо задай свой порт в настройках.

**Логи не появляются.** Проверь индикатор «на связи» в шапке. При обрыве WebSocket
страница переподключается сама. Нужен доступ к `/ws` — если стоит reverse-proxy,
его надо пропустить.
